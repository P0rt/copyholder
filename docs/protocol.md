# Runtime protocol between tap, host, worker, Deck and the page

This file fixes the wire formats between the live parts (spec sections 6.1-6.5, 7.1-7.3, 8.1). File formats themselves are in spec section 8.1 and in `core/schemas/`. Where this file and the spec differ, the spec wins; fix this file.

## Processes

| Part | File | Started by |
|---|---|---|
| `host` | `live/host.cjs` (CommonJS, needs only `ws` from the root package) | npm scripts (`session`, `gate`, `doctor`, `smoke`, `spacebar`, `live:from`, `live:sim`, `headstart`, ...) |
| `tap` | `live/tap.cjs` (the only file that loads the SDK) | `host`, via `child_process.fork` |
| mock `tap` | `live/mock-tap.cjs` (no SDK; synthetic trace or a recorded `detector_in.jsonl`; the same IPC messages and, in `smoke`, the same console lines as `tap`) | `host` in `live:sim`, `live:from` and tests |
| page | `web/` built by Vite into `web/dist/` | `host` opens it in Chrome |
| Deck | `web/deck.worklet.ts` (AudioWorkletProcessor named `deck`) | page |
| worker | `web/worker.ts` (module Web Worker) | page |

## host <-> tap (fork IPC, `process.send`)

tap -> host:

- `{t:'ready', port}`: the `/tap` WebSocket server listens on `127.0.0.1:port`.
- `{t:'cameras', list:[{id, name}]}`: camera list (sent before exit when no camera was chosen; in `smoke` always, before `camera`; again before exit after code 7). tap first prints the header `tap: cameras (copy one name into settings.env as COPYHOLDER_CAMERA_NAME=...):` on stderr and then the names on stdout, one per line (`(no name) id=<id>` for a camera without one). The two pipes keep no common order, so in `tap.log` a name can come before the header; `analysis/smoke.ts` then reads the list from `tap_cameras` (below). Without a camera to pick tap prints `tap: <n> cameras and no COPYHOLDER_CAMERA_NAME` or `tap: no camera name contains "<name>"` and exits.
- `{t:'status', kind:'processingStatus'|'validationStatus', code, name}`: on every change.
- `{t:'pulse', packets, last_ago_ms}`: once per second, the number of SDK `metrics` callbacks in the last second and the age in ms of the last one when the pulse is sent (null before the first) (spec 7.1, 7.2). host counts the 3 s of silence from that packet; a pulse without `last_ago_ms` stands in for it, up to a second late. The period and the 3 s are in `live/lib/tap-timing.cjs`.
- `{t:'camera', id, name, requested:[w, h, fps], metrics:[names], dry?}`: the camera tap picked and the metric set it asked for, after `config` (host puts them into `manifest.json`). `dry: true` only when tap ran its stand-in SDK (`--dry`, tests): no SDK ran, so host writes `dry: true` at the top level of `manifest.json` (`camera` takes no extra field in `core/schemas`); otherwise `dry` is false. Such a folder is no recording and never counts (spec 6.5): quickcheck refuses it before any check and writes nothing, printing `RE-RECORD NOW: dry run (tap's stand-in SDK), this folder never counts` (`DOCTOR FAIL: ...` for a doctor folder) with exit 2, and `analysis/smoke.ts` prints `SMOKE FAIL: dry run (tap's stand-in SDK)`, exits 2 and writes no `smoke_report.json` (`analysis/lib/dry-run.ts`).
- `{t:'enums', checks:[{label, differences}]}` (`smoke` only, after `camera`): for `ProcessingStatus`, `ValidationCode` and `SmartSpectraErrorCode`, the `name=code` pairs of `live/reduce.cjs` that the SDK's enum export does not have (empty: they match). tap prints one line per check on stdout (`live/reduce.cjs` `enumLine`): `<label>: matches reduce.cjs` or `<label>: differs from reduce.cjs: kName=code, ...`; the pairs stay readable in `tap.log` (below).
- `{t:'readiness', verdict, reason}`: the result of `checkDeviceReadiness()` (spec 7.12 question 1), after host's `{t:'readiness'}` or, in `smoke`, before `start()`. When the call has not settled in 30 s, tap first sends `{verdict:null, reason:'timeout'}` and keeps waiting, so a verdict may follow; when the call fails, `verdict` is null and `reason` is its message (with an SDK code, an `sdk_error` follows and tap skips `start()`). tap prints the verdict as `checkDeviceReadiness(): <verdict> (<reason>)`.
- `{t:'probe', packet, fields, tsType, tr, talk, frames, points, lipsY13BelowY14, cornersX78BelowX308, xRange, yRange, tsCbType}` (`smoke` only): packet 1 and the first packet with landmarks, through the accessors of `live/reduce.cjs` (`probeMetrics`): the decoded message's field names, the timestamp type, sample and frame counts, the mesh point count, two point order checks, the x and y extent of the points in frame pixels, and the type of the callback's `timestampUs` (spec 7.12 questions 2 and 4). tap also prints it as `packet <n>: {...}`.
- `{t:'sdk_error', code, name, message, retryable, call, action}`: any SDK `error` event or exception from `useCamera()`/`start()`. `call` names the SDK call when tap knows it (`useCamera()`, `CameraSelection.byId()`, `start()`, `checkDeviceReadiness()`, ...). For code 3 after `useCamera()` or `CameraSelection` host's line names the camera request first (`Check COPYHOLDER_CAMERA_NAME in settings.env.`) and, in `smoke`, the spare metric set next (`If the name is right, put COPYHOLDER_METRICS=spare in settings.env and run smoke again.`): spec 7.1 gives the code the same action from any call, and tap's `action` stays `exit_metrics`. From any other call code 3 names the metric set alone (spec 7.1 table, `live/lib/sdk-codes.cjs`). `action` is tap's row of the spec 7.1 table: `exit_key`, `exit_metrics`, `exit_cameras`, `reset_restart` (code 8 before the first packet: tap restarts once and host does not abort), `abort` (host aborts the recording, spec 7.2), or `exit` with `code: null` and `name: 'tap'` when tap itself failed without an SDK code (the SDK cannot be loaded, a call threw): tap exits.
- `{t:'started'}`, `{t:'paused'}` (after host's `{t:'pause'}`), `{t:'stopped'}`.
- `{t:'replay_done'}` (mock tap in `live-from` only): every recorded line was sent; the stand-in SDK then leaves `Running`, and host stops watching for silence.

host -> tap:

- `{t:'config', token, origin, sessionDir, smoke}`: sent once after `ready`. `token` guards `/tap`; `origin` is the only accepted `Origin`.
- `{t:'readiness'}`: only after consent: tap opens its files and runs `checkDeviceReadiness()` alone, then answers `{t:'readiness', verdict, reason}`. A later `start` waits for it and is skipped when it gave an SDK code. host does not send it yet; it is there to price the call on its own (spec 7.12 question 9, 11.5).
- `{t:'start'}`: only after the consent event from the page (spec 12.2). Before it the SDK is never started.
- `{t:'pause'}`: `await sdk.stopAsync()`; tap's files, process and `/tap` socket stay, tap answers `{t:'paused'}`, and a later `{t:'start'}` starts the SDK again with the same camera. host does not send it yet (spec 11.5).
- `{t:'stop'}`: `await sdk.stopAsync()`, then `{t:'stopped'}` and exit. host waits `TAP_STOP_BUDGET_MS` (25 s, `live/lib/tap-timing.cjs`) for the exit; tap's whole stop (SDK calls and closing its files) must fit inside. After it host kills tap and writes event `tap_killed` and `tap_killed: true` in `manifest.json`.
- `{t:'replay_start'}` (mock tap in `live-from` only): the page started the replayed audio (event `replay_start` below). The mock goes `Running` only now and sends each recorded line `(nArr - first audio sample of the recording) / 48` ms after it, so packets meet the audio as in the recording (spec 6.5).

The API key is read only by `tap` from `.env` (spec 13.6). `host` never reads `.env`. Both read `settings.env` with the same parser (`live/reduce.cjs` `parseEnvText`: `KEY=value` lines, optional `export` and quotes, a ` # note` after the value is dropped), and the environment wins over the file, even when empty.

The Electron run (spec 6.7, 7.12 question 1): in `smoke` under plain Node (`COPYHOLDER_LAUNCHER` is not `electron`), before tap's first SDK packet, host prints once `If the camera does not open in plain Node, run it again with: npm run live:electron -- smoke (spec 6.7).` when the camera may not have opened: an `sdk_error` with code 7, code 3 from `useCamera()` or `CameraSelection`, a failure without an SDK code in a camera call or in `start()`; an empty camera list; or tap's exit without an `sdk_error` and without an unmatched camera name. This line matters most before consent: then host keeps no folder and no smoke report runs (after a recording the smoke report gives the same advice).

tap's console: host forks tap with stdout and stderr piped (stdin ignored, IPC kept). Each line goes to host's own stdout or stderr, and from consent on into `sessions/<id>/tap.log`; lines from before consent wait in memory (at most 5000 lines and 1 MiB; a last line says how many more went to the terminal only) and are written first, and a run that never reaches consent writes no `tap.log`. Before a line is shown or written, credential-shaped text becomes `[redacted]` (`live/lib/tap-log.cjs`; host cannot look for the key itself, since it never reads `.env`): every run of 24 or more characters from `[A-Za-z0-9_+/=-]` that holds a letter and a digit, with two exceptions that the smoke report needs (spec 7.12 questions 2 and 10). An enum pair `kName=code` (`^k[A-Z][A-Za-z]*=\d+$`) stays. A URL or file path (two or more `/`, no `+` or `=`, at most a third of its letters upper case) is judged segment by segment: a segment of 24 or more characters with a letter and a digit, or of 8 or more that switches between letters and digits twice (an id, a hash, a key), becomes `[redacted]`, the words stay (`https://api.example.com/v2/insights/upload_snapshot` is kept, `/v1/sessions/<hex id>/insights` loses the id). A UUID goes whole, since a key may have that shape. A second pass changes nothing. After tap's exit host waits up to 1 s for the last lines, closes `tap.log` and only then runs quickcheck, whose smoke report reads it.

`tap.log` holds what tap prints: the camera names, the enum checks, the readiness verdict, the probe lines with the x and y extent of the face points in frame pixels, SDK errors, tap's error traces (the stack of uncaught and event-handler errors, with local file paths that can show the account name; the redaction keeps path words), and in `smoke` the SDK's own `kInfo` log. It is a log, not a recording file: it has no hash in `manifest.json` `files` or in `ledger.jsonl`, so it is never among the published files (spec 8.7). It stays on the Mac and reaches the assistant only with the user's yes for that file, like `samples.jsonl` (spec 12.5). `PRIVACY.md` lists it (Files on the computer; What goes to the AI assistant); spec 8.1 and 12.3 do not list it yet.

## HTTP (host)

- Listens on `127.0.0.1` at port `COPYHOLDER_PORT` (`settings.env` or the environment), 47811 when it is empty, with a random 32-byte hex token per run. A fixed port keeps the page's origin, so Chrome keeps the microphone permission in its own profile from one run to the next. This is an assumption against spec 7.2, which asks for a free port from the system; likewise `settings.env` holds more than the two variables of spec 13.6 (`COPYHOLDER_CAMERA_NAME`, `COPYHOLDER_METRICS`): host also reads `COPYHOLDER_MIC_NAME`, `COPYHOLDER_OUTPUT_NAME`, `COPYHOLDER_PORT` and `COPYHOLDER_FACE_PREVIEW`, all optional and not secret. Both stay until the spec is amended. When the port is taken (`EADDRINUSE`, or `EACCES`), host takes one the system picks and prints one line: `Port <p> is taken, so this run uses port <q>: Chrome may ask for the microphone again.` A value that is not a port number gets a line and 47811; `0` always lets the system pick (tests). The token, cookie, `Origin` and `Host` checks are the same on any port.
- `GET /?token=T` serves `web/dist/index.html` and sets cookie `ch_token=T; HttpOnly; SameSite=Strict; Path=/`. Every other HTTP request needs that cookie or `?token=T`; otherwise 403.
- `GET /api/config` returns the run config as JSON:
  `{mode, sessionId, scenario, tapUrl, sessionUrl, calib, narrator:[names], consentText:'live'|'mic'|'replay'}`.
  `consentText` `replay` (`live-from`, spec 6.5): neither the camera nor the microphone runs, so there is nothing to consent to; the page says what is replayed and still sends `{t:'consent', at}` when the user starts, which is host's start frame. Then `replayAudio` is set.
  `tapUrl` and `sessionUrl` carry their tokens as `?token=`.
  `replayAudio: 'mic.wav'` (`live-from` only): the narrator name of channel 0 of the replayed `audio.wav`. The page feeds it into Deck's input in place of the microphone (no `getUserMedia`), from Deck's first sample, and sends the event `replay_start` (below) with the sample where it starts.
  `devices: {input?, output?}`: a part of the microphone (`input`, from `COPYHOLDER_MIC_NAME`) and output device (`output`, from `COPYHOLDER_OUTPUT_NAME`) names to pick, from `settings.env` or the environment; the page picks the first device whose label holds it, ignoring case (`web/ui/devices.ts`). A key is left out when its setting is empty, and then the page keeps the system default input or output (spec 5.1, 5.2). Example: `COPYHOLDER_MIC_NAME=External Microphone` for a 3.5 mm headset on a MacBook.
  Optional field the page reads when present: `facePreview: true` for a demo take with the face preview (spec 12.2, 15.5).
  `detector: {params, sign, variant}` is the worker's `step()` setup (spec 7.4, 8.4): the parsed `params/frozen.json` (`{}` before it exists), the trace sign from `calib.json` of the gate recording with the verdict (1 before it) and `D1` (or `D3` when the frozen file names it). `calib` is the `calib.json` of the `doctor` recordings merged oldest first, plus that `polarity`; null when neither exists.
  host also adds `kind`, `pack`, `plan`, `source`, `tap`, `level` and `planCommitment`, for display only.
  `scenario` names the page knows (`web/scenarios/index.ts`): `gate-0`, `gate-A`, `gate-B`, `gate-C`, `doctor`, `doctor-level`, `smoke`.
- `GET /api/narrator/<name>` returns narrator audio (`*.wav`, mono 48 kHz) or `timings.json` for the current scenario. Only names in the scenario's allow list are served (spec 7.2, 8.2); anything else is 404. Sealed audio is decrypted in memory only and never before the `preflight_ok` event (spec 7.2). Fetching it does not spend the plan's text: the first `{"k":"state","s":"narrating"}` stamp after `preflight_ok` does (the first sealed sound, spec 10.4); host writes its `n` as `narrator.first_sealed_n` in `manifest.json` at once, and a plan whose earlier recording has it set does not start again.
  Gate packs (`gate/pack-*/`) serve `listen.wav`, `objections.wav`, their word timings `listen.timings.json` and `objections.timings.json` (the page also accepts `<clip>.json`, or a single `timings.json`) and `cues.json`: a JSON array of cue start times in ms from the start of the objection block. `doctor` serves the 20 s volume sample `level.wav` (spec 7.7) from `gate/level/` (`<COPYHOLDER_GATE_DIR>/level/`), where `gate/level/render.ts` writes it, and from `sample/` only when `gate/level/` has none. The names the page may fetch are the ones listed in `narrator`.
- `POST` is not used; everything else goes over `/session`.
- A page reload during a recording: the recording page asks for `/` and `/api/config` once, before consent, so a `GET` of either during a recording means the page is loading again. host writes event `page_reload` at once and ends the recording (spec 7.2, 7.3); a page whose socket closed and that does not load again within 4 s gives `page_lost`.

## WebSocket `/tap` (tap -> worker)

One text frame per `samples.jsonl` line, exactly as written to the file (spec 8.1): kinds `m` (packet), `v` (validationStatus), `s` (processingStatus), `f` (frameSentThrough), `e` (error), `l` (event-loop delay). One client only; wrong token or `Origin` is rejected.

## WebSocket `/session` (worker <-> host)

Text frames are JSON objects with a type field `t`:

- worker -> host
  - `{t:'hello', ua, settings}`: first frame; `settings` is `MediaTrackSettings` of the microphone (`getSettings()`), plus the output device name.
  - `{t:'consent', at}`: user pressed `I agree, start` (host may now send `{t:'start'}` to tap). In `live-from` it is the start frame (no consent screen there).
  - `{t:'stamp', line}`: one `stamps.jsonl` line (spec 8.1). Deck creates them; the worker forwards them in order.
  - `{t:'det', line}`: one `detector_in.jsonl` line, in processing order.
  - `{t:'event', line}`: one `events.jsonl` line.
  - `{t:'end', reason}`: the reason of the page's `{k:'end'}`: scenario finished (`done`), the user pressed `Stop` (`stop`), `abort`, or `deck_error` (Deck's processor failed).
- host -> worker
  - `{t:'abort', reason}`: SDK `error` or `tap_lost`: Deck mutes the narrator at once, the second loop check is skipped (spec 7.2). `reason` is `sdk_error`, `tap_lost`, `page_reload`, `host_interrupted`, or `recording_closed` for a page that connects after the recording ended. While the recording page's socket is still open (its last blocks and `end` after an abort), a newer socket gets `recording_closed` and is closed; `saved` and `quickcheck` go to the recording page.
  - `{t:'tap', status}`: tap lifecycle (`starting`, `running`, `stopped`).
  - `{t:'saved', sessionId, unusable, reasons}`: the files are closed and hashed.
  - `{t:'quickcheck', ok, text}`: `text` is the last stdout line of `quickcheck` (`GOOD RECORDING` or `RE-RECORD NOW: <reason>`, spec 7.12; for doctor and smoke recordings `DOCTOR OK`, `DOCTOR FAIL: <reason>`, `SMOKE OK`, `SMOKE FAIL: <reasons>`). `ok` comes from its exit code: true for 0, false for 2, null for anything else (a crash or a kill). Both are null when none ran. host closes the socket after it.
    quickcheck runs as `npx tsx analysis/quickcheck.ts <id>` in its own process group (spawned detached). host ends that group always the same way: SIGTERM to the group, so quickcheck's own handlers stop what it started in groups of their own (doctor's TTS self-test, `analysis/lib/tts.ts`), then SIGKILL 0.5 s later. host goes on at quickcheck's exit plus 0.5 s for its last stdout lines, then ends whatever is left of the group, so no `tsx` or `node` child outlives host. After 10 minutes host ends the whole group and sends `ok: null` with `text` `The quick check did not finish in 10 minutes. Run it again: npm run quickcheck -- <id>`. The group does not get the terminal's Ctrl+C: on Ctrl+C host ends it and sends `ok: null` with `The quick check was stopped. Run it later: npm run quickcheck -- <id>`. When host itself exits (a second Ctrl+C, an internal error) it sends the SIGTERM, waits up to 0.5 s while the group lasts and then sends the SIGKILL before it is gone.
    After the report, a record kind without a ledger (`doctor`, `smoke`, `headstart`, `live_from`, `live_sim`), whose file hashes live in `manifest.json` alone, gets them checked again: host hashes every file `files` lists and, when the report rewrote one, writes the new hashes into `files` and changes nothing else in `manifest.json`. The case is `doctor`: host writes the chosen `output_gain` into `calib.json` at the level choice, so `files` holds it, and on `DOCTOR OK` doctor rewrites that file with `L_rt`, the leak and the voice detector values (spec 7.12, 8.1: `calib.json` has three writers). On `DOCTOR FAIL` the file stays as host wrote it: the chosen level only, which later recordings use (spec 7.7). A ledger kind keeps `manifest.json` as its `record` step hashed it; later writes are steps of the ledger (spec 8.5).

Binary frames (worker -> host) carry audio blocks: a 16-byte header, then planar float32 data.

```text
bytes 0-3   ASCII "CHK1"
bytes 4-7   uint32 LE  frames (normally 9600)
bytes 8-15  float64 LE n0 (first sample number of the block)
then        float32 LE ch0[frames] (microphone), float32 LE ch1[frames] (Deck output)
```

`host` appends the block to `audio.wav` (2 channels, float32, 48 kHz, interleaved) and writes the `chunk` stamp `{"n":n0,"k":"chunk","frames":frames}`. A block whose `n0` is not the previous `n0 + frames` marks the audio unusable: `host` writes event `audio_gap` (spec 6.3, 7.2).

## Deck <-> worker (direct MessagePort, bypassing the main thread)

The page creates a `MessageChannel`, gives one end to the worker and the other to Deck (through `AudioWorkletNode.port`, once at start).

- worker -> Deck: `{k:'pkt', seq, hold}` for every SDK packet, after `step()`. Deck stamps `{"n":nArr,"k":"arr","seq":seq}` in the quantum where it handles the message; in live modes `hold:true` starts the 8 ms fade with `nCmd = nArr`. The worker keeps `step()` answers (`hold:true`, events `fire` and `armed`) only where chest holds stop the narrator: `session`, `rehearsal`, `demo`, `live-from`, and `headstart` once the page has set the trace sign (below). In every other mode `step()` runs on the preliminary parameters and its answers are dropped (spec 7.3).
- Deck -> worker:
  - `{k:'chunk', n0, frames, ch0, ch1}` (Float32Array, transferred) every 9600 frames;
  - `{k:'stamp', line}` for every stamp (`arr`, `hold`, `state`, `voice`, `resume`, `ignored`, `click`, `mark`);
  - `{k:'vad', n, source, note?, params}`: the voice detector parameters Deck runs with from sample `n` on, `params` as a whole `vad` block of `params/frozen.json` (snake_case). The first one has `n` 0 and comes before any other message: `source` is `options` (processorOptions `vadParams`) or `default` (`DEFAULT_VAD_PARAMS`); `note` is why the given parameters were unusable, else processorOptions `vadSource` when given. Each `{k:'vad'}` from the page adds one with `source` `message` at the sample where Deck switched. The worker writes it to `events.jsonl` as `{n, e:'vad', source, note?, params}`. Analysis recomputes the voice edges per segment: `vadEdges` of the samples before a switch with the earlier parameters, then of the samples from the switch with the new ones (spec 7.3);
  - voice edges and narrator state changes also arrive as stamps; the worker turns them into `detector_in.jsonl` lines `{k:'voice', n, on}` and `{k:'state', n, s}` and feeds them to `step()` in arrival order (spec 7.3, 7.4);
  - `{k:'done', n}` after Deck's last block (a shorter one, ending at sample `n`) and its last stamp. The worker sends `{t:'end'}` only when it has both this and the page's `{k:'end'}` (or 3 s after the page's end when Deck is gone), so `{t:'end'}` is its last frame. `/tap` lines after `done` are no detector input. `fire` and `armed` lines wait for their packet's `arr` stamp; those of a packet Deck never stamped (it came after Deck's last quantum) are dropped at the end, since their time would be that packet's `nArr` (spec 6.3).

Stamp shapes beyond the spec 8.1 examples (core/schemas accepts them): `{"n":n,"k":"mark","i":1,"what":"cue","on":true}` (a cue step), `{"n":nKey,"k":"mark","what":"key"}` (space bar), `{"n":nKey,"k":"ignored","what":"key","s":"hold_wait"}`, and the state `idle` while no clip plays (before the first play step, after a clip ends, after `end` or `stop`). A `hold` stamp carries `seq` only for `cause:'chest'`; `word` is the interrupted word (the next word in a pause; null without timings or after the last word).

## Deck <-> main thread (`AudioWorkletNode.port`)

- main -> Deck: `{k:'port', port}` (the Deck end of the worker channel, transferred, the first message), `{k:'load', name, pcm, timings}`, `{k:'scenario', steps}`, `{k:'go'}`, `{k:'gain', value}`, `{k:'key'}` (space bar `keydown`), `{k:'stop'}`, `{k:'vad', params, source?}`.
  `{k:'vad'}` gives new voice detector parameters during the run (a floor measured in the run, spec 7.11), read like processorOptions `vadParams`. They must name the floor (`floorDb`, or `floor_db` of a frozen block). Deck switches at the first quantum boundary where its detector reports no voice (a voice_on of the old detector would otherwise lack its voice_off) and records the switch (`{k:'vad'}` to the worker above; `source` goes into `note`). Without a floor, with parameters `core/vad` cannot use, or with a test detector Deck refuses them with `{k:'error'}` and keeps its parameters.
- Deck -> main: `{k:'step', n, name, text}` (a scenario step started: the page shows its prompt), `{k:'cue', n, on}` (the dot fills or empties), `{k:'click', n, i, block}` (a click starts at sample `n`; `i` counts within `block`, `A`, `B` or `demo`; the page flashes the square on every click, spec 15.4), `{k:'state', n, s, cause}` (`cause` is `chest`, `voice` or `key` in `hold_wait` and `listening` after a stop, else null), `{k:'level', ch0Db, ch1Db}` (meters, about 10 per second), `{k:'done', n}`, `{k:'error', message}` (a message, clip, scenario or parameters Deck cannot use, a second scenario, or a sample rate other than 48 kHz; Deck goes on). The page shows an error as a note `Deck: <message>` and goes on; it does not end the run (a processor failure does, through `processorerror` below).

Scenario timing lives inside Deck and is counted in samples. The main thread only draws what Deck reports. No deadline in the app depends on `setTimeout` or `requestAnimationFrame` (spec 6.1). Steps that wait for an outside condition (SDK `Running` with `kOk` held 5 s, a button on the page) are released by `{k:'go'}`.

The page creates the `AudioWorkletNode` named `deck` with one mono input (the microphone) and one mono output (to `destination`): `{numberOfInputs:1, numberOfOutputs:1, outputChannelCount:[1], channelCount:1, channelCountMode:'explicit'}`.

`processorOptions: {mode, gain, vadParams?, vadSource?}`. `mode` is the `/api/config` mode: `session`, `rehearsal`, `demo`, `headstart` and `live-from` let chest holds and the audio safety stop the narrator; `spacebar` lets the space bar and the audio safety stop it; in `live-sim` only the audio safety stops it (a flat synthetic trace, D1 not active, spec 10.2); any other mode never stops it (spec 6.4, 6.5). `gain` is the output gain until the first `{k:'gain'}`. `vadSource` (optional) says where the page took `vadParams` from; Deck puts it in the `note` of its first `vad` record. `vadParams` must be for 48 kHz (a frozen block has no sample rate). `vadParams` holds every `VadParams` field of `core/vad`, chosen in the order analysis uses after the run (`analysis/lib/calib-io.ts` `chooseVadParams`), so the live voice edges and the recomputed ones share one parameter set: the `vad` block of `params/frozen.json` (`/api/config` `detector.params.vad`), with doctor's floor and periodicity threshold (`calib.vad.floor_db`, `calib.vad.periodicity`) in place of the block's when the block has no `floor_db` (its other keys stay; PREREG §5); else `calib.vad` of doctor (`floor_db`, `periodicity`); else the page leaves it out and Deck runs `DEFAULT_VAD_PARAMS`. A block `core/vad` cannot use counts as absent. Deck also reads a snake_case `vad` block as it is. Whatever the page passes, Deck records the parameters it actually runs with from sample 0 (the `vad` record above), so the recomputation after the run can take them from `events.jsonl`.

When the processor throws, the node fires `processorerror` (Chromium dispatches it as an `ErrorEvent` of type `error`, so the page sets `onprocessorerror` rather than adding a `processorerror` listener) and Deck records nothing more and sends no `done`. The page then sends the worker a hard `deck_error` event and ends the run with reason `deck_error` (spec 7.2, 12.2); an error before the run screen is up is kept until then.

### Scenario steps

`steps` is the array built by `web/scenarios/` (types in `web/scenarios/format.ts`). Every step has a unique `name`, a prompt `text` (`''` keeps only the dot) and `lenSamples`, the samples from its start to the start of the next step. Deck reports `{k:'step', n, name, text}` and stamps `{"k":"mark","what":"step","name":...}` at each start. Kinds:

- `prompt` (optional `bar: 'grow'|'shrink'`, the deep-breath bar), `rest`: show `text`.
- `cue` (`i`, `on`): the dot fills (`on:true`) or empties; Deck also reports `{k:'cue', n, on}` and stamps a `cue` mark.
- `play` (`clip`): start the loaded clip at its first sample at the step start; it plays until its last sample, a later `play` or `end`. With `untilClipEnd:true` the next step starts when the clip ends instead of after `lenSamples`. Where something can stop the narrator (every mode but the gate ones above), a stop lengthens the passage, so Deck refuses a scenario whose `play` steps lack `untilClipEnd:true`: a timed step could start the next clip in `hold_wait` or `listening` (spec 6.4).
- `clicks` (`block: 'A'|'B'|'demo'`): the 10 loop-check clicks (spec 6.3) within the step, or the demo take's three sync clicks at 250, 1050 and 2150 ms from the step start (`demo`, spec 7.3, 15.4; the times are an assumption). Each click is stamped and reported to the page (`{k:'click'}`).
- `wait` (`until: 'sdk_ok'|'button'`, `lenSamples: 0`): the next step starts at the sample where `{k:'go'}` is handled. A scenario with another `until` is refused (`scenarioErrors`), since the page releases only these two.
- `align` (`anchor`, `offsetSamples`, `lenSamples: 0`): the next step starts at `start(anchor) + offsetSamples`, or at once if that sample has passed.
- `end` (`lenSamples: 0`): stop playback, report `{k:'done', n}`. A clip still playing fades out over 384 samples and a click plays to its end first; `n` is the first sample not recorded. `{k:'stop'}` ends the same way from the quantum where it is handled.

`web/scenarios/runner.ts` (`ScenarioRunner`) runs these rules on sample numbers alone, with no timers; Deck and the stand-in Deck can call it once per render quantum.

## Main thread <-> worker (`postMessage`)

The page creates the worker only after `I agree, start` (spec 12.2), so nothing connects to `/tap` or `/session` before consent.

- main -> worker, in this order at start:
  - `{k:'init', config, port}`: the `/api/config` JSON and the worker end of the Deck channel (transferred).
  - `{k:'hello', ua, settings}`: for the first `/session` frame. `settings` is the microphone `getSettings()` plus `label`, `contextSampleRate`, `baseLatency`, `outputLatency` and `output: {name, sinkId, accepted}`.
  - `{k:'consent', at}`: `at` is the ISO time of the `I agree, start` click; the worker sends `{t:'consent', at}`.
- main -> worker, later:
  - `{k:'event', e, hard, ...fields}`: a window or device event (spec 7.3), for `events.jsonl` with the worker's current sample number. `e` is `visibilitychange` (`state`; hard when `hidden`), `blur`, `resize` (`w`, `h`), `devicechange` (hard), `track_ended` (hard), `track_mute` (hard), `gain` (`value`, `db`, `final`; the level chosen in `doctor`, spec 7.7), or `deck_error` (`message`; hard: Deck's processor failed and no audio is recorded after it).
  - `{k:'detector', sign}`: the trace sign of this run from the three cued deep breaths (spec 7.4, 7.11), sent before the narrator first reads. `step()` starts again with this sign on every input so far (nothing is active before reading), so a replay of `detector_in.jsonl` with this sign gives the same answers. The worker writes `{n, e:'detector_sign', det, sign}` to `events.jsonl`. It refuses the sign with `{k:'error'}` after reading started, outside a live run with a detector, or when it is not 1 or -1. In `headstart` the worker does not use the stored sign: until this message `step()` runs with sign 1 and its answers are dropped; if reading starts without it, the worker reports an error and D1 never stops the narrator in that run.
  - `{k:'end', reason}`: `done`, `stop` (the `Stop` button), `abort`, `deck_error` (Deck's processor failed) or `session_lost` (the worker lost `/session`); the worker sends `{t:'end', reason}` and replies `{k:'closed'}` after its last frame. The worker keeps `/session` open for host's last messages.
- worker -> main:
  - `{k:'sdk', tap, ok, note?}`: `tap` is `starting`, `running` or `stopped` (the camera runs while `starting` or `running`); `ok` is true while `Running` with `kOk` held 5 s (spec 7.1). `note` names the latest status code that is not `kOk`, for the waiting screen, or is `tap socket closed` once the `/tap` socket has closed (`ok` then stays false).
  - `{k:'abort', reason}`: from host `{t:'abort'}`; the page sends Deck `{k:'stop'}` and turns the microphone off.
  - `{k:'quickcheck', ok, text}`: host's `{t:'quickcheck'}`, passed on. The page shows `text` in place of the end prompt (spec 9.3, 10.4), or under the message after `Stop`, an abort or a failure, and then ends the worker.
  - `{k:'closed'}`: the page closes the `AudioContext`; the worker stays for `quickcheck`, except after `session_lost`, when the page ends it.
  - `{k:'error', message}`: shown under the prompt. `worker: /session closed before the end of the run` means nothing more reaches host: the page ends the run with `session_lost`. `worker: /tap closed before the end of the run` means the `/tap` socket closed or was refused (token, `Origin`, a second client) while the run went on and host had not reported `{t:'tap', status:'stopped'}`: no SDK packet reaches the worker any more.

## Event names used across parts (working names, spec 8.1)

`preflight_ok`, `tap_lost`, `audio_gap`, `sdk_error`, `consent`, `armed`, `fire`, `hold`, `resume`, `vad` (Deck's voice detector parameters from sample `n` on), `detector_sign` (the trace sign set before reading), window and device events (`visibilitychange`, `blur`, `resize`, `devicechange`, `track_ended`, `track_mute`), `deck_error` (the page: Deck's processor failed), `gain` (the output level chosen in `doctor`), `replay_start` (`live-from`: the sample `n` where the replayed audio starts in Deck; host passes it on to the mock tap).

Lines `host` writes itself carry `"by":"host"` and `n` = the sample after the last stored audio block (null before audio): `consent` (`at`), `tap` (`status`), `audio_gap` (`expected`, `got`, `missing`), `audio_bad_block` (`detail`), `audio_full`, `page_reload` (`page_loads`, `via`: `/`, `/index.html`, `/api/config` or `/session`), `page_lost`, `tap_lost` (`why`: `silence` with `silent_ms` from tap's last packet, plus `status` when the SDK had left `Running` by itself; or `exit` with `code`, `signal`), `sdk_error` (`code`, `name`, `message`), `host_interrupted` (`signal`), `tap_killed` (`after_ms`). Each of them except `consent`, `tap`, `tap_killed` and an `sdk_error` with `action:'reset_restart'` marks the recording unusable: `manifest.json` gets `unusable: true` and the names in `unusable_reasons`. In `doctor` a `gain` line with `final: true` makes `host` write `output_gain` into that recording's `calib.json` (spec 7.7, 8.1).

tap's answers in `smoke` (spec 7.12 questions 1, 2, 4 and 10), written by host for `analysis/smoke.ts` (`ipcMessageOf` reads them like tap's messages): `tap_cameras` (`list: [{name}]`), `tap_camera` (`name`, `requested`, `metrics`, and `dry: true` for tap's stand-in SDK), `tap_readiness` (`verdict`, `reason`; the early timeout line too), `tap_probe` (`ipc`: the probe message, under `ipc` because an `events.jsonl` line may not carry `points` at its top level) and `tap_enums` (`checks`). Those that came before consent follow the `consent` line with `n` null, the others carry the current `n`. They leave out what must not leave the Mac by default (spec 12.5): camera ids and the probe's `xRange` and `yRange` (face coordinates; `tap.log` keeps tap's own probe line). Outside `smoke` host writes none of them: the camera's name would reach `events.jsonl`, which is published unchanged (spec 8.7), while `manifest.json` is where publishing aliases it. None of them marks the recording unusable.

Only the worker writes `fire`, `armed`, `hold`, `resume`, `vad` and `detector_sign`; a page `{k:'event'}` with one of these names is refused.
